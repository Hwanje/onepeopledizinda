# 지옥의 추첨

한 명씩 지워나가는 당첨자 추첨기. 매 라운드 게임 하나가 정해지고, 반드시 한 명이 탈락한다.
정해진 탈락자 수가 채워지면 끝까지 살아남은 사람이 당첨이다.

서버 없이 정적 파일만으로 돌아간다. GitHub Pages에 올리면 끝.

## 게임

| 게임 | 방식 |
| --- | --- |
| **러시안 룰렛** | 6연발 리볼버에 실탄 한 발. 차례대로 방아쇠를 당긴다. 한 사람당 한 번, 탄창을 다시 돌리고 당길 수 있다. |
| **유리 징검다리** | 매 칸 왼쪽/오른쪽 중 하나만 강화유리. 한 사람씩 한 칸씩 뛴다. 틀리면 추락. |
| **시한폭탄** | 남은 시간이 보이지 않는 폭탄. 받으면 다른 사람을 골라 넘긴다. 터질 때 들고 있던 사람이 죽는다. |
| **독배** | 사람 수만큼의 잔, 독은 하나. 차례로 잔을 고른 뒤 무작위 순서로 마신다. |
| **사신의 바퀴** | 무작위로 뽑힌 한 명이 바퀴를 돌린다. 바늘이 멈춘 사람이 탈락. 자기 자신일 수도 있다. |

게임은 라운드마다 **무작위**로 정하거나 **방장이 직접 지정**할 수 있다. 사용할 게임만 골라 켤 수도 있다.

## 진행 방식

| 방식 | 규칙 |
| --- | --- |
| **단판** | 한 번 죽으면 바로 탈락. 탈락자 수만큼 라운드를 진행한다. |
| **목숨제** | 방장이 정한 횟수(2~9번)만큼 죽어야 탈락. 죽어도 목숨이 남아 있으면 다음 라운드에 되살아난다. 라운드마다 반드시 한 명이 죽고, 탈락자가 정한 수만큼 나오면 끝난다. |

방장은 참여자 수, 탈락자 수, 탈락 기준 죽음 횟수를 정한다. 목숨은 참가자 목록에 마름모 칸으로 표시된다.

## 진행

1. 방장이 **방을 연다** → 참여자 수, 탈락자 수, 게임 결정 방식, 제한 시간을 정한다.
2. 대기실의 **초대 링크 / QR / 5자리 코드**를 공유한다. 참가자는 링크를 열고 이름만 입력하면 된다.
3. 같은 공간에 있는 사람은 방장이 **현장 참가자**로 직접 추가할 수 있다. 이들의 차례는 방장 화면에서 대신 누른다.
4. 차례인 사람이 제한 시간 안에 행동하지 않으면 자동으로 진행된다.
5. 탈락 연출 후, 탈락자 화면은 흑백 관전 모드로 바뀐다.

## GitHub Pages 배포

1. 저장소를 공개로 전환한다. (비공개 저장소의 Pages는 유료 플랜에서만 된다.)
2. **Settings → Pages → Build and deployment**에서 Source를 `Deploy from a branch`, 브랜치를 `main` / `/ (root)`로 지정한다.
3. 잠시 뒤 `https://<계정>.github.io/<저장소>/` 에서 열린다.

빌드 과정은 없다. `index.html`이 진입점이다.

코드를 고쳐 배포할 때는 `index.html` 아래쪽 import map과 css/qrcode 주소의 `?v=` 숫자를 함께 올린다. 그래야 방장과 참가자 브라우저에 옛 파일이 캐시로 남지 않는다.

## 로컬 실행

ES 모듈을 쓰므로 `file://`로는 열리지 않는다. 아무 정적 서버나 띄우면 된다.

```sh
python3 -m http.server 8080
# http://localhost:8080
```

## 구조와 동작 방식

- **통신**: 공개 MQTT 브로커(WebSocket over TLS)를 중계로 쓴다. 기본으로 `broker.emqx.io`, `broker.hivemq.com`, `test.mosquitto.org` 세 곳에 동시에 붙고 받은 쪽에서 중복을 거르므로, 한 곳이 막혀도 동작한다. 일반 HTTPS 연결이라 모바일망/회사망/NAT와 상관없다.
- 방장 브라우저가 게임 서버 역할을 하며, 모든 무작위 판정은 방장 쪽에서 `crypto.getRandomValues`로 한다. 참가자는 화면만 받는다.
- 브로커를 직접 지정하려면 주소 뒤에 `?mqtt=wss://호스트:포트/mqtt`(쉼표로 여러 개)를 붙인다. 이 값은 초대 링크에도 그대로 따라간다.
- 공개 브로커이므로 메시지는 암호화된 비밀 통신이 아니다. 방 코드를 아는 사람은 내용을 볼 수 있다. 파티 게임 용도로만 쓸 것.
- **방장 탭을 닫으면 방이 사라진다.** 새로고침은 괜찮다. 같은 탭에서 상태를 복구하고 진행 중이던 라운드부터 다시 이어간다. 참가자도 새로고침하면 자동으로 재접속한다.
- 중계 서버에 연결하지 못해도 방장 화면 하나로 현장 참가자만 넣고 진행할 수 있다. (화면 공유용)
- **소리**: 음원 파일 없이 Web Audio로 전부 합성한다. 진행 멘트는 브라우저 음성 합성(한국어)을 쓴다.

```
index.html
css/style.css
js/
  app.js        화면, 라우팅, 방장/참가자 연결
  engine.js     방장 전용 진행 엔진 (라운드, 차례, 탈락)
  net.js        MQTT 다중 브로커 통신 (자체 구현, 외부 라이브러리 없음)
  audio.js      효과음 합성
  fx.js         섬광, 흔들림, 피, 파편
  games/        게임별 진행 로직(run)과 화면(View)
vendor/         QR 생성기
```

### 게임 추가하기

`js/games/`에 파일을 만들고 `index.js`에 등록한다. 각 게임은 두 부분으로 되어 있다.

- `run(c)` — 방장 쪽에서만 실행되는 async 함수. `c.turn(참가자, 행동, 옵션)`으로 입력을 기다리고, `c.set()`으로 공개 상태를, `c.emit()`으로 연출 이벤트를 보내고, 마지막에 `c.kill(id, 사인)`으로 반드시 한 명을 탈락시킨다. 정답(실탄 위치 등)은 함수 안 지역 변수로만 들고 있어 참가자에게 새지 않는다.
- `View` — 모든 화면에서 돌아가는 클래스. `update(state)`로 상태를 그리고 `event(ev)`로 효과음과 애니메이션을 낸다.
